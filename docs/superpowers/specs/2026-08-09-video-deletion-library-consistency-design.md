# DABOM 영상 삭제와 라이브러리 정합성 설계

## 문서 성격

- 기존 앱 시작 백그라운드 스캔에 신규 영상 결과 알림과 파일 없음 상태를 추가하는 변경 설계다.
- 선택 영상의 `DEL` 삭제와 확인 절차, 토스트 스택을 함께 정의한다.
- 별도 정합성 검사나 자동 목록 제거를 만들지 않고 기존 스캔 결과를 재사용한다.

## 목표

1. 신규 영상의 메타데이터와 포스터 수집 결과를 영상별 토스트로 알린다.
2. 목록에는 있지만 실제 파일이 없는 영상을 자동 제거하지 않고 명확히 표시한다.
3. 저장소 연결 실패를 실제 파일 누락과 구분한다.
4. 사용자가 `DEL`로 실제 파일과 목록 또는 목록만 안전하게 제거할 수 있게 한다.
5. 대량 결과도 앱 사용을 방해하지 않도록 최대 5개의 애니메이션 토스트와 FIFO 대기열로 표시한다.
6. 기존처럼 스캔을 백그라운드에서 수행하고 진행 상태를 하단 메시지바에 표시한다.

## 선택한 접근

기존 `LibraryScanner` 결과와 저장된 영상 목록을 비교하는 방식을 사용한다.

- 선택안: 현재 백그라운드 스캔에 접근 불가 경로 정보와 진행 보고를 보강하고, `MainViewModel`에서 신규·기존·파일 없음 항목을 분류한다.
- 제외안 1: 스캔 후 별도 정합성 검사를 실행하면 같은 파일을 중복 확인하고 실행 시간과 상태 관리가 늘어난다.
- 제외안 2: 실시간 파일 감시는 네트워크 저장소, 대량 변경과 경합 처리가 필요해 이번 앱 시작 검사 범위를 넘어간다.

새 서비스 계층이나 외부 패키지는 추가하지 않는다. 현재 스캐너, 메타데이터 수집 흐름, 저장소와 WPF 애니메이션 기능을 재사용한다.

## 앱 시작과 스캔 흐름

1. 저장된 영상 목록을 먼저 화면에 표시한다.
2. 기존 백그라운드 스캔을 시작하고 하단 메시지바에 검사 중임과 현재까지 확인한 영상 수를 점진적으로 표시한다.
3. 스캔 결과와 저장 목록을 경로 기준으로 비교한다.
4. 실제 파일이 발견된 기존 항목은 파일 크기, 수정 시각과 재생 시간을 기존 방식대로 갱신한다.
5. 실제 파일만 발견된 항목은 신규 영상 레코드로 추가하고 이번 스캔의 신규 경로로 기록한다.
6. 저장 목록에만 있는 항목은 목록과 화면에 유지하고 실행 중 `파일 없음` 상태를 부여한다.
7. 접근할 수 없는 저장 위치나 하위 경로에 속한 항목은 파일 없음 비교에서 제외한다.
8. 스캔 완료 후 신규 경로의 메타데이터 수집을 기존 흐름으로 실행한다.

파일 없음 상태는 JSON에 저장하지 않고 스캔할 때마다 다시 계산한다. 다음 정상 스캔에서 파일이 발견되면 상태와 시각 표시를 해제하되, 저장 목록에 이미 있던 항목이므로 신규 영상 토스트는 표시하지 않는다.

## 저장소 연결 실패

- 등록된 저장 위치 또는 그 하위 경로를 읽을 수 없으면 해당 범위를 파일 없음으로 판정하지 않는다.
- 접근 불가 범위에 속한 저장 목록 항목은 그대로 유지한다.
- 저장 위치마다 `보관 위치에 연결할 수 없습니다: {경로}` 토스트를 한 번 요청한다.
- 기존 스캔 경고 정보는 유지하며, 판정에 필요한 접근 불가 경로를 스캔 결과에 포함한다.

## 신규 영상과 메타데이터 결과

토스트는 이번 스캔에서 처음 추가된 영상에 대해서만 요청한다.

### 성공

다음 항목이 모두 완료되어야 성공이다.

1. 파일명 분석
2. 메타데이터 검색과 상세 정보 수집
3. 포스터 확보와 로컬 저장
4. 변경된 영상 레코드 저장

성공 메시지는 메타데이터 기준 표시명을 사용한다.

`“{영상명}”이 추가되었습니다.`

### 실패

검색 결과 없음, 인증 실패, 네트워크·공급자 오류, 파일명 분석 실패, 포스터가 없거나 다운로드·저장할 수 없음, 레코드 저장 실패 중 하나라도 발생하면 전체 수집 결과를 실패로 처리한다.

실패 메시지는 원본 파일명을 사용한다.

`“{파일명}”의 메타데이터 수집에 실패했습니다.`

신규 영상은 목록에 유지하고 메타데이터 상태를 `Failed`로 저장해 기존 정책대로 다음 앱 실행에서 재시도한다. 포스터 단계에서 실패했다면 이미 받은 메타데이터는 유지하되 성공으로 알리지 않는다.

## 파일 없음 판정과 표시

접근 가능한 경로를 정상적으로 스캔했지만 저장된 영상 경로가 결과에 없을 때만 파일 없음으로 판정한다.

- 각 누락 영상마다 `“{파일명}” 파일이 존재하지 않습니다.` 토스트를 요청한다.
- 누락 항목은 자동으로 목록이나 저장 데이터에서 제거하지 않는다.
- 개별 영상 카드는 포스터 이미지의 불투명도를 `0.5`로 적용해 정상보다 50% 어둡게 표시한다.
- 개별 영상 카드의 포스터 하단에 빨간띠와 `파일 없음` 문구를 표시한다.
- TV 시즌에 누락 에피소드가 하나라도 있으면 시즌 포스터 이미지에도 불투명도 `0.5`를 적용한다.
- 시즌 카드의 기존 상단 `TV 시즌` 띠는 유지하고 하단에 빨간띠와 `파일 없음 포함` 문구를 표시한다.
- 빨간띠는 포스터 위에 표시해 어둡기 효과의 영향을 받지 않는다.

## 토스트 스택

토스트는 앱 창 오른쪽 아래의 하단 메시지바 위에 표시하며 스캔, 메타데이터와 삭제 오류가 같은 FIFO 대기열을 사용한다.

- 한 번에 최대 5개를 표시한다.
- 각 토스트의 유지 시간은 실제로 화면에 나타난 시점부터 5초다.
- 새 토스트는 스택 아래에서 나타나고 기존 토스트는 위로 밀린다.
- 등장, 이동과 퇴장 애니메이션은 각각 200ms다.
- 여러 메시지가 동시에 요청돼도 한 애니메이션 주기마다 한 항목만 화면에 추가해 최초 5개도 한꺼번에 나타나지 않게 한다.
- 5개가 표시 중이면 새 메시지는 메모리 대기열에 보관한다.
- 표시 중인 토스트가 만료되면 가장 먼저 대기한 메시지를 빈자리에 표시한다.
- 영상별 결과를 합치거나 생략하지 않는다.
- 앱 종료 시 표시 중인 토스트와 남은 대기열은 폐기한다.

토스트 표시 수명과 애니메이션은 UI가 담당한다. 스캔과 메타데이터 코드는 문자열 알림만 요청하며 UI 타이머를 기다리지 않는다. 따라서 대기열이 길어져도 백그라운드 작업 완료가 지연되지 않는다.

## `DEL` 삭제 동작

`DEL`은 영상 또는 시즌 상세의 개별 에피소드가 선택됐을 때만 삭제를 시도한다.

### 실제 파일이 있는 영상

다음 의미의 확인창에 파일명을 표시하고 `확인`, `취소`를 제공한다.

`“{파일명}” 파일을 삭제하시겠습니까? 파일과 영상 목록에서 제거됩니다.`

- `확인`: 실제 영상 파일을 먼저 삭제한 뒤 저장 목록과 현재 화면에서 제거한다.
- `취소`: 데이터나 파일을 변경하지 않고 확인창만 닫는다.
- 실제 파일 삭제가 실패하면 목록을 제거하지 않고 오류 토스트를 표시한다.
- 파일 삭제 후 목록 저장이 실패하면 항목을 파일 없음 상태로 유지하고 오류 토스트를 표시한다.

### 실제 파일이 없는 영상

다음 확인창에 파일명을 표시하고 `확인`, `취소`를 제공한다.

`“{파일명}” 파일이 존재하지 않습니다. 영상 목록에서 제거하시겠습니까?`

- `확인`: 실제 파일 작업 없이 저장 목록과 현재 화면에서만 제거한다.
- `취소`: 데이터를 변경하지 않고 확인창만 닫는다.
- 목록 저장이 실패하면 기존 목록과 화면 상태를 유지하고 오류 토스트를 표시한다.

### TV 시즌 카드

시즌 카드 자체에서 `DEL`을 누르면 일괄 삭제하지 않고 다음 토스트를 표시한다.

`TV 시즌은 한 번에 삭제할 수 없습니다. 시즌을 열고 개별 영상을 선택하세요.`

## 데이터 일관성과 오류 처리

- 목록 데이터는 파일 작업과 저장 작업이 모두 성공한 뒤 화면에서 제거한다.
- 삭제 실패나 저장 실패를 성공으로 표시하지 않는다.
- 누락 판정은 접근 불가 경로를 제외해 일시적인 외장·네트워크 저장소 연결 실패로 목록을 훼손하지 않는다.
- 같은 스캔에서 같은 영상에 대한 파일 없음 토스트는 한 번만 요청한다.
- 메타데이터 부분 성공은 보존할 수 있지만 포스터와 저장까지 완료되지 않으면 상태와 토스트는 실패다.
- 기존 스캔 경고, 메타데이터 진행 상태와 완료 요약은 유지한다.

## 최소 구현 경계

- `LibraryScanner`는 현재 백그라운드 열거를 유지하면서 진행 수와 접근 불가 경로를 결과로 전달한다.
- `MainViewModel`은 저장 목록과 스캔 결과를 비교하고 신규 경로, 파일 없음 상태, 메타데이터 결과와 삭제 결과를 관리한다.
- `VideoItemViewModel`과 `SeasonItemViewModel`은 파일 없음 및 누락 포함 여부를 화면에 제공한다.
- `MainWindow.xaml`은 포스터 어둡기, 하단 빨간띠와 오른쪽 아래 토스트 스택을 표시한다.
- `MainWindow.xaml.cs`는 기존 키 입력 흐름에서 `DEL` 확인창과 UI 토스트 대기열·애니메이션을 처리한다.
- 기존 `LibraryData`와 JSON 형식, 메타데이터 공급자 인터페이스, 영상 재생 흐름은 변경하지 않는다.
- 새 패키지, 실시간 파일 감시와 별도 정합성 서비스는 추가하지 않는다.

## 검증과 수용 기준

검증은 GUI를 띄우지 않는 단위 테스트, XAML 정적 검사와 Debug 빌드를 우선한다.

1. 저장 목록에 없는 파일을 발견하면 신규 영상으로 추가한다.
2. 신규 영상의 메타데이터, 포스터와 저장이 성공하면 메타데이터 표시명으로 성공 토스트를 요청한다.
3. 신규 영상의 포스터 다운로드를 포함한 어느 단계라도 실패하면 파일명으로 실패 토스트를 요청하고 `Failed` 상태를 유지한다.
4. 접근 가능한 경로에서 파일이 사라지면 목록을 유지하고 파일 없음 상태와 영상별 토스트를 생성한다.
5. 접근할 수 없는 저장 위치나 하위 경로의 항목은 파일 없음으로 판정하지 않고 연결 실패 토스트를 생성한다.
6. 개별 파일 없음 카드는 포스터 불투명도 `0.5`와 하단 `파일 없음` 빨간띠를 표시한다.
7. 누락 에피소드가 포함된 시즌 카드는 상단 `TV 시즌` 띠와 하단 `파일 없음 포함` 띠를 함께 표시하고 포스터 불투명도를 `0.5`로 표시한다.
8. 토스트는 동시에 최대 5개만 표시하고, 동시 요청도 한 항목씩 등장시키며, FIFO 대기열에서 만료 순서대로 보충한다.
9. 토스트는 5초 유지되며 등장·이동·퇴장에 200ms 애니메이션을 사용한다.
10. 실제 파일이 있는 영상의 삭제를 확인하면 파일과 목록을 제거하고, 취소하거나 파일 삭제가 실패하면 둘 다 유지한다.
11. 실제 파일이 없는 영상의 삭제를 확인하면 목록만 제거하고 취소하거나 저장이 실패하면 목록을 유지한다.
12. 시즌 카드에서 `DEL`을 누르면 일괄 삭제하지 않고 안내 토스트를 표시한다.
13. 앱 화면 표시와 입력을 막지 않고 백그라운드 스캔 상태가 하단 메시지바에 점진적으로 표시된다.
14. 기존 영상 검색, 필터, 정렬, 시즌 그룹, 재생과 메타데이터 편집 테스트가 계속 통과한다.
15. `dotnet test tests/Dabom.Tests/Dabom.Tests.csproj -c Debug`와 `dotnet build Dabom.sln -c Debug`가 성공한다.
16. 구현 변경 후 `graphify update .`가 성공한다.

## 제외 범위

- 파일 없음 항목의 자동 제거 또는 시작 시 일괄 제거 확인창
- 시즌 카드의 일괄 파일 삭제
