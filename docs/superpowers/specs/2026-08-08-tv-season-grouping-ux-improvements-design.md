# DABOM TV 시즌 그룹 탐색 UX 개선 설계

## 문서 성격

- 기존 TV 시즌 그룹 기능에 대한 UI·동작 delta 스펙이다.
- 기준 스펙은 `2026-08-05-tv-season-grouping-design.md`이며, 이 문서는 시즌 카드 식별성, 그룹 카드 팝업, 시즌 상세 Hero와 복귀 UI만 변경한다.
- 기존 검색·필터·정렬, 시즌 그룹 판정, 선택·포커스 복원, 재생 이력 저장과 자동 그룹 해체 동작은 명시적으로 변경한 부분을 제외하고 유지한다.

## 목표

1. 전체 목록에서 시즌 그룹 카드를 일반 영상 카드와 즉시 구분할 수 있게 한다.
2. 그룹 카드에서도 기존 영상 카드와 같은 hover 정보 탐색 경험을 제공한다.
3. 시즌 상세 화면의 상단 Hero가 추천 영상 대신 현재 시즌과 다음 미시청 에피소드를 소개하게 한다.
4. 시즌 상세 화면임을 명확히 표시하고 마우스와 키보드로 전체 목록에 쉽게 돌아가게 한다.
5. 전체 목록과 시즌 상세 화면에서 검색 툴바의 구조와 조작 위치를 동일하게 유지한다.

## 선택한 접근

비교한 세 접근 중 `Hero 안에서 한 번에` 구성을 사용한다.

- 선택안: 기존 큰 Hero 안에 전체 목록 복귀, 시즌 정보, 대표 에피소드 소개와 재생 동작을 통합한다.
- 제외안 1: 복귀 경로를 검색 툴바에 두는 방식은 시즌 정체성과 복귀 동작이 Hero와 툴바로 분리된다.
- 제외안 2: 작은 시즌 소개 띠로 Hero를 축소하는 방식은 에피소드 목록을 빨리 보여주지만 기존 화면의 시각적 리듬을 크게 바꾼다.

선택안은 기존 Featured Hero, 카드 팝업, 재생 흐름을 재사용하면서 네 개선 목표를 가장 적은 구조 변경으로 해결한다.

## 용어

- **전체 그룹**: 현재 검색·필터 결과와 무관하게 현재 라이브러리에서 같은 시즌 그룹 키를 가진 모든 에피소드다.
- **대표 에피소드**: 그룹 카드 팝업과 시즌 상세 Hero에서 다음에 볼 항목으로 소개하는 실제 영상이다.
- **현재 결과 편수**: 현재 검색·필터 조건에 일치하여 시즌 상세 목록에 표시되는 에피소드 수다.
- **총 편수**: 전체 그룹에 포함된 실제 에피소드 수다.

## 대표 에피소드 선택 규칙

대표 에피소드는 전체 그룹에서 다음 순서로 정한다.

1. `LastPlayedUtc`가 없는 에피소드가 하나 이상이면 재생 이력이 없는 에피소드만 후보로 삼는다.
2. 후보 중 양수 회차 번호가 가장 작은 에피소드를 선택한다.
3. 모든 에피소드에 재생 이력이 있으면 전체 그룹 중 양수 회차 번호가 가장 작은 에피소드를 선택한다.
4. 회차 번호가 없거나 양수가 아닌 항목은 양수 회차 번호가 있는 항목 뒤에 둔다.
5. 회차 번호가 같거나 유효한 회차 번호가 전혀 없으면 기존 전체 그룹 순서의 첫 항목을 선택한다.

검색어, 필터와 정렬을 바꿔도 대표 에피소드 선택 범위는 전체 그룹으로 유지한다. 예를 들어 1·2화를 재생했고 3화가 현재 검색 결과에서 숨겨져 있어도 Hero는 3화를 소개하고 재생한다.

## 전체 목록의 시즌 카드

- 기존 포스터 프레임 상단에 전체 폭의 고대비 강조 리본을 표시한다.
- 리본 문구는 `TV 시즌`으로 고정해 그룹 유형 식별에 집중한다.
- 카드 아래의 시리즈명과 `시즌 N · N편` 요약은 유지한다.
- 카드 아래 `N편`은 기존 계약대로 현재 검색·필터 조건에 일치하는 편수다.
- 기존 선택·키보드 포커스 테두리와 자동화 이름을 유지해 색상과 리본만으로 그룹 여부를 전달하지 않는다.
- 한 번 클릭 또는 선택 후 `Enter`로 시즌 상세를 열고, 그룹 카드 자체를 재생 대상으로 취급하지 않는다.

## 그룹 카드 팝업

- 기존 `CardPopup`의 위치 계산, 화면 가장자리 회피, 클릭 통과와 표시 수명을 그대로 사용한다.
- 팝업 콘텐츠만 실제 영상용과 시즌 그룹용 템플릿으로 나눈다.
- 시즌 그룹 팝업은 다음 정보를 제공한다.
  - 그룹 포스터
  - `TV 시즌 그룹` 레이블
  - 시리즈명
  - `시즌 N · 총 N편`
  - `다음 미시청: N화 · 에피소드 제목`; 모두 재생했다면 `처음부터: N화 · 에피소드 제목`
  - 대표 에피소드의 시놉시스
  - `클릭 또는 Enter로 시즌 열기` 안내
- 그룹 전체를 대표하지 않는 상영일, 감독, 배우와 파일명은 시즌 그룹 팝업에 표시하지 않는다.
- 대표 에피소드 시놉시스가 비어 있으면 시놉시스 영역을 비워 두며 별도 대체 문구나 네트워크 조회를 추가하지 않는다.

## 시즌 상세 Hero

- 시즌 상세에 진입하면 기존 Featured Hero의 자리에 시즌 소개 Hero를 표시한다.
- `FeaturedVideo` 값과 추천 선정 상태는 변경하지 않는다. 전체 목록으로 복귀하면 기존 추천 Hero가 다시 표시된다.
- 시즌 소개 Hero는 다음 순서로 정보를 제공한다.
  1. `← 전체 영상` 복귀 버튼
  2. 시리즈명
  3. `TV 시즌 · 시즌 N · 총 N편`
  4. `다음 미시청 에피소드` 또는 모든 편 재생 시 `처음부터 보기` 레이블
  5. 대표 에피소드의 회차, 제목, 포스터와 시놉시스
  6. 대표 에피소드 `재생하기` 버튼
- 대표 에피소드에 포스터가 없으면 기존 `NO POSTER` 표시를 사용한다.
- Hero의 총 편수와 대표 에피소드는 검색·필터 결과가 0편이어도 전체 그룹을 기준으로 유지한다.
- 검색·필터 결과가 0편이면 기존 빈 결과 UI를 Hero 아래에 표시하며 시즌 상세 상태를 유지한다.

## Hero 재생 동작

- 시즌 소개 Hero의 재생 버튼은 현재 대표 에피소드를 기존 `PlayAsync` 흐름으로 실행한다.
- 별도의 프로세스 실행, 재생 기록 또는 저장 경로를 만들지 않는다.
- 영상 실행과 재생 이력 저장이 모두 성공하면 대표 에피소드를 다시 계산한다.
- 다음 미시청 회차가 있으면 Hero가 그 회차로 이동한다.
- 모든 회차에 재생 이력이 생기면 Hero는 가장 첫 회차와 `처음부터 보기`를 표시한다.
- 영상 실행이 실패하면 기존 재생 실패 메시지를 표시하고 대표 에피소드를 바꾸지 않는다.
- 영상은 실행됐지만 재생 이력 저장이 실패하면 기존 저장 실패 메시지를 표시하고 메모리의 재생 이력을 바꾸지 않으므로 Hero도 현재 대표 에피소드를 유지한다.

## 복귀와 현재 위치

- 기존 검색 툴바의 조건부 `전체 영상` 행은 제거한다.
- 전체 목록 복귀 버튼과 시즌 위치는 Hero 안에서 제공한다.
- `Esc`로 전체 목록에 돌아가는 기존 키보드 동작을 유지한다.
- 복귀할 때 기존 시즌 그룹 키, 스크롤 위치와 카드 포커스 복원 동작을 유지한다.
- 그룹이 해체되어 자동 복귀할 때도 기존처럼 임의의 영상을 선택하지 않는다.
- 시즌 상세 여부는 Hero의 시즌 레이블, 제목, 대표 에피소드와 복귀 버튼으로 즉시 구분할 수 있어야 한다.

## 공통 검색 툴바

- 전체 목록과 시즌 상세는 같은 검색창, 필터, 정렬, 고정 위치와 Tab 순서를 사용한다.
- 전체 목록에서는 전체 라이브러리를 검색하고 시즌 상세에서는 현재 시즌의 에피소드만 검색한다.
- 툴바의 시각 구조와 각 조작의 위치는 두 화면에서 바꾸지 않는다.
- 문맥 텍스트만 다음처럼 변경한다.
  - 전체 목록: `내 영상`과 현재 전체 결과 수
  - 시즌 상세: `에피소드`와 현재 결과 편수
- 시즌 상세의 검색·필터는 대표 에피소드와 총 편수를 바꾸지 않는다.

## 상태와 데이터 흐름

1. 전체 목록 재구성 시 기존 시즌 그룹 계산 결과로 시즌 카드와 총 편수를 만든다.
2. 같은 전체 그룹에서 대표 에피소드를 선택해 시즌 카드 팝업 정보에 사용한다.
3. 시즌 카드를 열면 기존 활성 시즌 키를 유지하고 현재 시즌 소개 정보를 노출한다.
4. Hero와 그룹 카드 팝업은 같은 대표 에피소드 선택 규칙을 사용한다.
5. 검색·필터·정렬은 기존 목록 재구성 흐름만 갱신하고 대표 선택 범위를 전체 그룹으로 유지한다.
6. 재생 이력 저장 성공 또는 메타데이터 저장으로 그룹 데이터가 바뀌면 기존 목록 재구성 지점에서 시즌 소개 정보를 다시 계산한다.
7. 활성 그룹이 2편 미만이 되면 기존 흐름대로 전체 목록으로 자동 복귀한다.

시즌 소개 정보는 실행 중 화면 상태이며 저장하지 않는다. 기존 `VideoRecord`, `LibraryData`, 공급자 참조와 JSON 형식을 변경하지 않는다.

## 최소 구현 경계

- `SeasonItemViewModel`이 전체 그룹 편수와 대표 에피소드 선택 결과를 제공한다.
- `MainViewModel`이 활성 시즌 소개와 현재 Hero 영상을 노출하고, 기존 Hero 재생 명령을 현재 표시 중인 영상에 연결한다.
- `MainWindow.xaml`은 기존 Hero와 카드 팝업 안에서 전체 목록·시즌 상세 및 영상·시즌 템플릿을 전환한다.
- `MainWindow.xaml.cs`의 hover 위치 계산, 시즌 진입·복귀, 포커스와 스크롤 코드는 재사용한다.
- 새 서비스, 인터페이스, 저장 모델, 네트워크 호출, 패키지와 프로젝트 파일은 추가하지 않는다.

## 접근성

- 시즌 카드 자동화 이름은 시리즈명, 시즌 번호, 현재 결과 편수와 `시즌 열기` 동작을 계속 포함한다.
- `TV 시즌` 리본 외에도 자동화 이름과 카드 내용으로 그룹 유형을 전달한다.
- Hero의 복귀 버튼은 `전체 영상으로 돌아가기` 자동화 이름을 제공한다.
- 시즌 제목과 대표 에피소드 변경은 보조 기술이 인식할 수 있는 제목과 적절한 live setting으로 제공한다.
- 방향키, `Enter`, `Tab`, `F1`, `Esc`만으로 시즌 진입, 에피소드 탐색·재생·편집과 복귀를 수행할 수 있어야 한다.

## 제외 범위

- 시즌 또는 시리즈 전용 시놉시스 저장
- 추가 TMDB 요청이나 시즌 메타데이터 다운로드
- 그룹 카드에서 대표 에피소드 직접 재생
- 시즌 소개 상태 저장과 앱 재시작 후 상세 화면 복원
- 새 창, 중첩 탐색, 인라인 펼침 또는 별도 상세 패널
- 애니메이션, 코치 마크와 첫 실행 안내

## 검증과 수용 기준

검증은 GUI를 띄우지 않는 단위 테스트, XAML 정적 검사와 Debug 빌드를 우선한다.

1. 1·2화에 재생 이력이 있고 3·4화에 없으면 대표 에피소드는 3화다.
2. 모든 에피소드에 재생 이력이 있으면 대표 에피소드는 가장 첫 회차다.
3. 검색·필터로 대표 에피소드가 목록에서 숨겨져도 Hero의 대표 에피소드는 바뀌지 않는다.
4. 유효한 회차 번호가 없는 후보는 유효한 번호가 있는 후보보다 뒤에 선택된다.
5. Hero에서 대표 에피소드 재생과 이력 저장이 성공하면 다음 미시청 회차로 이동한다.
6. 실행 또는 이력 저장 실패 시 대표 에피소드는 바뀌지 않고 기존 오류 메시지가 유지된다.
7. 전체 목록의 시즌 카드에 전체 폭 `TV 시즌` 리본이 표시된다.
8. 실제 영상 카드와 시즌 그룹 카드가 같은 팝업 컨테이너에서 각 형식에 맞는 내용을 표시한다.
9. 시즌 상세에서는 추천 Hero가 아닌 시즌 소개 Hero와 `전체 영상으로 돌아가기` 조작이 표시된다.
10. 전체 목록으로 복귀하면 기존 `FeaturedVideo`, 시즌 카드 포커스와 스크롤 위치가 유지된다.
11. 전체 목록과 시즌 상세의 검색 툴바 구조·조작 순서는 같고 문맥 텍스트와 검색 범위만 달라진다.
