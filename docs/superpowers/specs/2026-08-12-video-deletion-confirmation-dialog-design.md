# 영상 삭제 확인 창 개선 설계

## 목표

Windows 기본 `MessageBox`로 표시되는 영상 삭제 확인을 Dabom 테마의 전용 창으로 교체한다. 사용자는 긴 경로를 읽지 않고도 삭제 대상과 결과를 빠르게 이해할 수 있어야 한다.

## 범위

- 기존 삭제 상태 판정과 `DeleteVideoAsync` 동작은 변경하지 않는다.
- `MainWindow`의 Delete 키 흐름에서 전용 확인 창을 연다.
- 확인 창은 기존 `DabomTheme.xaml`의 창, 색상, 버튼 스타일을 재사용한다.
- 전체 파일 경로는 표시하지 않는다.
- 별도의 범용 대화상자 프레임워크는 만들지 않는다.

## 화면 구성

확인 창은 소유 창 중앙에 열리는 고정 크기 모달 창이다.

1. 창 제목: `영상 삭제`
2. 본문 제목: `영상을 삭제할까요?`
3. 파일명: 별도의 한 줄에 표시하고, 공간을 넘으면 말줄임표로 줄인다.
4. 상태별 설명:
   - 파일 있음: `파일을 휴지통으로 이동하고 목록에서도 제거합니다.`
   - 파일 없음: `파일을 찾을 수 없어 목록에서만 제거합니다.`
5. 작업 버튼:
   - 파일 있음: `휴지통으로 이동`
   - 파일 없음: `목록에서 제거`
6. 보조 버튼: `취소`

작업 버튼은 기존 테마의 삭제 강조색을 사용하고, 취소 버튼은 일반 버튼 스타일을 사용한다. 전체 경로, 경고 아이콘, 중복 설명은 넣지 않는다.

## 상호작용과 접근성

- 창은 `ShowDialog`로 열어 확인 전에는 다른 작업을 막는다.
- `Esc`와 창 닫기 버튼은 취소로 처리한다.
- 처음 열릴 때 취소 버튼에 키보드 포커스를 두어 실수로 삭제하지 않게 한다.
- 작업 버튼과 취소 버튼에 의미가 드러나는 자동화 이름을 제공한다.
- 사용자가 작업 버튼을 선택한 경우에만 기존 `DeleteVideoAsync`를 호출한다.

## 구성 요소와 데이터 흐름

전용 WPF 창은 `VideoDeletionRequest`에서 파일명과 파일 상태만 받아 화면을 구성하고, 확인 여부만 반환한다.

```text
Delete 키
  → PrepareVideoDeletion()
  → 삭제 확인 창(파일명, 상태)
  → 확인: DeleteVideoAsync(request)
  → 취소: 종료
```

삭제 확인 창은 파일 상태를 다시 확인하거나 파일을 직접 삭제하지 않는다. 삭제 안전성과 목록 정합성은 기존 ViewModel 흐름이 계속 책임진다.

## 오류 처리

상태를 확정할 수 없을 때는 기존 `PrepareVideoDeletion`이 요청 생성을 거부하므로 확인 창이 열리지 않는다. 확인 이후 발생하는 파일 이동 또는 목록 저장 오류도 기존 토스트 처리 방식을 유지한다.

## 검증

- 파일이 있을 때 올바른 안내와 `휴지통으로 이동` 버튼이 표시되는지 확인한다.
- 파일이 없을 때 올바른 안내와 `목록에서 제거` 버튼이 표시되는지 확인한다.
- 전체 경로가 화면 문구에 포함되지 않는지 확인한다.
- 취소가 기본 포커스이며 `Esc`와 창 닫기가 삭제를 실행하지 않는지 확인한다.
- 기존 Delete 키 흐름이 확인된 경우에만 `DeleteVideoAsync`를 호출하는지 확인한다.
- 전체 테스트, Debug 빌드, Release 빌드를 실행한다.
