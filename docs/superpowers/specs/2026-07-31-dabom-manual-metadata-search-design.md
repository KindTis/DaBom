# Dabom 수동 메타데이터 검색·선택 설계

- 문서 상태: 승인됨
- 작성일: 2026-07-31
- 대상: 기존 `MetadataWindow`의 메타데이터 검색·선택 기능

## 1. 배경

Dabom은 파일명에서 추출한 정보로 메타데이터를 자동 검색하고 첫 후보를 적용한다. 이 방식은 잘못된 후보가 선택되거나 검색 결과를 얻지 못할 수 있다. 현재 편집창에서는 표시값만 직접 수정할 수 있으며, 잘못된 공급자 참조를 올바른 작품으로 교체하거나 `NotFound` 항목을 다시 검색할 수 없다.

사용자가 기존 메타데이터 편집창에서 작품명을 직접 검색하고, 영화와 TV 결과 중 하나를 선택한 뒤 필요한 필드만 수정하여 저장할 수 있도록 한다.

## 2. 목표

- 영화와 TV를 구분하지 않는 단일 검색란을 제공한다.
- 검색 결과에서 올바른 작품을 사용자가 선택할 수 있게 한다.
- 선택한 결과를 저장 전 편집 폼에서 검토하고 수정할 수 있게 한다.
- 선택 결과의 공급자 참조와 상태를 올바르게 갱신한다.
- 선택 후 사용자가 실제로 수정한 필드만 `UserEditedFields`에 기록한다.
- 포스터와 JSON 저장이 실패해도 기존 레코드와 기존 포스터를 보존한다.
- 기존 자동 보강과 검색하지 않은 일반 편집 동작을 유지한다.

## 3. 제외 범위

- 검색 결과 페이지 이동
- 입력 중 자동 검색과 디바운스
- 메타데이터 공급자 선택 UI
- TV 시리즈 단위 레코드 저장
- 자동 매칭 신뢰도 계산 변경
- 실앱 UI 자동화와 실제 TMDB 네트워크를 사용하는 기본 테스트
- 새로운 검색 프레임워크나 별도 서비스 계층

## 4. 핵심 결정

- 기존 공급자 중립 계약과 `MetadataEnrichmentService`를 확장한다.
- 편집창이 TMDB 형식이나 인증 방식을 직접 알지 않게 한다.
- 검색 결과는 편집 폼의 레이아웃에 참여하지 않는 WPF `Popup`으로 표시한다.
- 결과 선택은 편집 폼만 갱신하며 실제 저장은 기존 `저장` 버튼에서 수행한다.
- 검색 결과 선택 후의 값을 새 비교 기준으로 삼는다.
- 최종 저장 시 비교 기준과 다른 필드만 사용자 편집으로 기록한다.
- 원격 포스터는 미리보기만 하고 최종 저장 시 로컬로 다운로드한다.

## 5. 기존 구조와 변경 경계

현재 호출 흐름은 다음과 같다.

```text
MainWindow
  → MetadataWindow
  → MetadataEditorViewModel
  → MainViewModel.CommitMetadataAsync
  → LibraryStore
```

자동 메타데이터 흐름은 다음과 같다.

```text
MainViewModel
  → MetadataEnrichmentService
  → IMetadataProvider
  → TmdbMetadataProvider
```

수동 검색은 두 흐름을 연결하되 새 중간 계층을 만들지 않는다. `MainViewModel`이 기존 콜백 주입 방식으로 검색과 후보 상세 조회 기능을 `MetadataEditorViewModel`에 제공한다. 실제 공급자 호출은 `MetadataEnrichmentService`가 담당한다.

## 6. 공급자 계약

### 6.1 통합 검색

`MetadataQuery.MediaType`이 `Unknown`이면 영화와 TV가 섞인 통합 검색을 의미한다. 자동 보강에서 사용하는 `Movie`와 `TvEpisode` 검색 의미는 바꾸지 않는다.

현재 TMDB 구현은 통합 검색에서 영화와 TV 결과만 반환한다. 인물 등 지원하지 않는 결과 유형은 제외한다.

### 6.2 검색 후보 표시 정보

`MetadataCandidate`에 다음 선택적 표시 정보를 추가한다.

- 표시 제목
- 원제
- 출시 또는 첫 방영 연도
- 검색 결과용 포스터 URI

기존 공급자 식별자, 자원 유형, 자원 ID, 미디어 유형, 시즌 번호, 에피소드 번호는 유지한다. 새 필드는 선택적이며 기존 자동 보강 호출자는 변경 없이 동작한다.

TV 통합 검색 결과는 `ResourceType`을 `tv-series`, `MediaType`을 `TvEpisode`로 표현한다. 실제 회차 상세 조회 전 시즌과 에피소드 번호를 후보에 결합한다.

### 6.3 수동 조회 진입점

`MetadataEnrichmentService`에 다음 책임만 추가한다.

- 등록된 공급자를 이용한 통합 후보 검색
- 선택 후보를 소유한 공급자를 찾아 상세 메타데이터 조회
- 기존 재시도와 공급자 오류 분류 재사용
- 저장 시 기존 포스터 다운로드 경로 재사용

통합 후보 검색은 등록 순서대로 공급자를 호출하고, 결과를 하나 이상 반환한 첫 공급자의 후보만 표시한다. 정상 응답이지만 결과가 없으면 다음 공급자로 이동한다. 모든 공급자가 결과를 반환하지 못하면 기존 자동 보강과 같은 기준으로 `결과 없음`과 공급자 오류를 구분한다. 현재 등록 공급자는 TMDB 하나이므로 공급자 혼합, 중복 제거와 공급자 배지는 구현하지 않는다.

편집 ViewModel은 `IMetadataProvider` 또는 `TmdbMetadataProvider`를 직접 참조하지 않는다.

## 7. 편집창 UI

### 7.1 검색란

- 오른쪽 편집 폼의 최상단에 검색란과 `온라인 검색` 버튼을 둔다.
- 검색란은 현재 제목으로 초기화한다. 제목이 비어 있으면 파일명에서 확장자를 제거한 값을 사용한다.
- `Enter`와 버튼 클릭으로 검색한다.
- 입력 중에는 자동으로 API를 호출하지 않는다.

### 7.2 Floating 검색 결과

- 결과는 검색란 바로 아래에 WPF `Popup`으로 표시한다.
- Popup은 폼을 아래로 밀거나 창 크기를 바꾸지 않는다.
- 최대 높이를 제한하고 결과가 많으면 내부 스크롤한다.
- 항목에는 포스터, 제목, 원제, 연도, `영화` 또는 `TV` 배지를 표시한다.
- 항목 선택, 바깥 클릭, `Esc`로 닫는다.
- 방향키로 항목을 이동하고 `Enter`로 선택할 수 있게 한다.
- 첫 페이지 결과만 표시한다.

### 7.3 TV 회차 입력

TV 결과는 개별 에피소드 메타데이터로 적용한다.

- 현재 레코드에 시즌과 에피소드 번호가 모두 있으면 그대로 사용한다.
- 하나라도 없으면 Popup 안에서 두 번호를 입력받는다.
- 두 값이 모두 양의 정수일 때만 상세 조회한다.
- TV 시리즈 자체의 메타데이터 저장은 지원하지 않는다.

## 8. 편집 상태

`MetadataEditorViewModel`은 다음 상태를 관리한다.

- 검색어
- 검색 후보 목록
- 검색 또는 상세 조회 진행 여부
- Popup 표시 여부
- 선택한 후보와 상세 메타데이터
- 선택 결과 적용 직후의 비교 기준값
- 검색과 상세 조회 오류 메시지

검색 또는 상세 조회 중에는 중복 조회와 저장을 비활성화한다. 창을 닫으면 진행 중인 조회를 취소한다.

상세 조회가 성공하기 전에는 기존 편집 폼을 바꾸지 않는다. 성공하면 선택 상세 정보로 다음 값을 교체한다.

- 제목과 원제
- 개봉일 또는 방영일
- 감독
- 배우
- 줄거리
- 장르
- 포스터 미리보기
- 미디어 유형
- 시리즈와 에피소드 정보
- 시즌과 에피소드 번호
- 공급자 참조

다른 결과를 다시 선택하면 저장하지 않은 이전 후보와 편집값을 새 결과로 교체하고 비교 기준도 다시 설정한다.

## 9. 사용자 편집 필드 판정

검색 결과를 선택하지 않은 경우에는 현재 동작을 유지한다. 원본 레코드와 최종 폼을 비교하고 기존 상태와 공급자 참조를 보존한다.

검색 결과를 선택한 경우에는 선택 결과 적용 직후의 값을 비교 기준으로 사용한다.

- 선택 결과와 같은 값은 공급자 값으로 저장한다.
- 선택 후 사용자가 바꾼 값만 `UserEditedFields`에 추가한다.
- 이전 레코드의 공급자 관리 필드 보호 상태는 선택 결과로 교체한다.
- 사용자가 별도 포스터를 선택하거나 제거하면 `Poster`를 사용자 편집 필드로 기록한다.
- 검색어 변경은 메타데이터 필드 편집으로 기록하지 않는다.

예를 들어 선택 결과의 제목이 `기생충`이고 사용자가 줄거리만 수정하면 `UserEditedFields`에는 `Synopsis`만 기록한다.

## 10. 저장

### 10.1 선택 결과가 없는 경우

기존 `CommitMetadataAsync` 동작을 유지한다.

- 사용자가 직접 바꾼 필드만 저장한다.
- 기존 `MetadataStatus`와 `ProviderReferences`를 유지한다.
- 기존 로컬 포스터 선택과 제거 동작을 유지한다.

### 10.2 선택 결과가 있는 경우

다음 값을 하나의 저장 작업으로 반영한다.

- 최종 편집 폼 값
- 선택 상세 정보의 장르와 구조화된 TV 정보
- 선택 결과의 `ProviderReferences`
- `MetadataStatus.Matched`
- 선택 후 사용자가 수정한 필드 집합
- 최종 로컬 포스터 경로

포스터 처리 우선순위는 다음과 같다.

1. 사용자가 로컬 포스터를 선택했으면 해당 파일을 가져온다.
2. 사용자가 포스터를 제거했으면 빈 값으로 저장한다.
3. 그 외에는 선택 상세 정보의 원격 포스터를 저장 시 다운로드한다.
4. 선택 상세 정보에 포스터가 없으면 빈 값으로 저장한다.

새 포스터 준비 후 `LibraryStore.SaveAsync`가 성공해야 메모리 ViewModel과 화면을 갱신한다. 저장 성공 후에만 교체된 이전 포스터를 삭제한다.

포스터 다운로드, 포스터 검증 또는 JSON 저장이 실패하면 새 파일을 정리하고 기존 레코드와 기존 포스터를 유지한다. 다이얼로그는 닫지 않고 오류를 표시한다.

취소하면 검색 결과, 선택 상세 정보, 편집값과 원격 포스터 미리보기를 모두 버린다. 원격 포스터는 저장 전 로컬 파일로 만들지 않는다.

## 11. 오류 처리

| 상황 | 처리 |
|---|---|
| 검색어가 비어 있음 | 공급자를 호출하지 않고 검색어 입력 안내 |
| 검색 결과가 없음 | Popup 안에 `검색 결과가 없습니다` 표시 |
| 토큰 누락, HTTP 401 또는 403 | 비밀값 없이 `.env` 확인 안내 |
| 네트워크 오류, 시간 초과, HTTP 429 또는 5xx | 현재 폼을 유지하고 재시도 안내 |
| 잘못된 공급자 응답 | 현재 폼을 유지하고 조회 실패 안내 |
| TV 시즌 또는 에피소드가 유효하지 않음 | 상세 조회 없이 양의 정수 입력 안내 |
| 후보 상세 조회 실패 | 기존 폼과 기존 선택 상태 유지 |
| 검색 결과 포스터 조회 실패 | 텍스트 결과는 표시하고 포스터만 비움 |
| 선택 포스터 다운로드 실패 | 저장하지 않고 기존 레코드와 포스터 유지 |
| JSON 저장 실패 | 새 포스터 정리, 기존 레코드와 포스터 유지 |

오류 메시지와 예외 문자열에는 접근 토큰을 포함하지 않는다.

## 12. 조용한 단위 테스트

기본 테스트는 사용자의 컴퓨터 경험과 데이터를 건드리지 않아야 한다.

- 실제 앱 창, 다이얼로그, 브라우저를 열지 않는다.
- `Show`와 `ShowDialog`를 호출하지 않는다.
- 실제 TMDB 네트워크를 호출하지 않는다.
- 가짜 `HttpMessageHandler`로 요청과 응답을 검증한다.
- 실제 `%LocalAppData%`, `.env`, 라이브러리와 포스터를 사용하지 않는다.
- 파일 검증은 테스트 전용 임시 폴더에서 수행하고 종료 시 정리한다.
- UI 동작은 ViewModel 직접 호출과 XAML 마크업 검사로 검증한다.
- WPF가 필요한 경우 테스트 프로세스 내부의 숨겨진 Dispatcher만 사용한다.
- 기본 `dotnet test`는 화면 변화, 소리, 외부 프로세스, 외부 네트워크 요청을 만들지 않는다.

실앱 UI 자동화나 실제 TMDB 통합 검증이 필요하면 기본 테스트와 분리하고 사용자가 명시적으로 실행할 때만 수행한다.

### 12.1 공급자 테스트

- 영화와 TV가 섞인 통합 검색 결과 매핑
- 제목, 원제, 연도, 유형과 포스터 정보
- 지원하지 않는 결과 유형 제외
- 기존 영화와 TV 개별 검색 유지
- 인증, 일시 오류와 잘못된 응답 분류

### 12.2 편집 ViewModel 테스트

- 빈 검색어 차단
- 검색 중 중복 검색과 저장 차단
- 후보 선택 후 폼과 비교 기준 갱신
- TV 시즌과 에피소드 번호 검증
- 선택 후 수정한 필드만 사용자 편집으로 판정
- 다른 후보 선택 시 비교 기준 재설정
- 검색과 상세 조회 실패 시 기존 폼 보존
- 취소 시 영속 데이터와 로컬 파일 무변경

### 12.3 저장 테스트

- 선택 결과를 `Matched`와 새 공급자 참조로 저장
- 장르, 미디어 유형, 시즌과 에피소드 정보 저장
- 원격 포스터를 저장 시점에만 다운로드
- 사용자가 선택하거나 제거한 포스터 우선
- 포스터와 JSON 저장 실패 시 롤백
- 검색 결과를 선택하지 않은 기존 편집 동작 유지

### 12.4 마크업과 전체 검증

- 검색란 아래 Floating Popup 배치
- 결과 스크롤과 키보드 접근성 바인딩
- Debug 빌드
- 전체 MSTest
- 코드 변경 후 `graphify update .`

## 14. 완료 조건

- 잘못 매칭된 영상과 `NotFound` 영상에서 통합 검색을 실행할 수 있다.
- 영화와 TV 후보를 한 결과 목록에서 구분해 선택할 수 있다.
- TV 후보는 유효한 시즌과 에피소드로 개별 회차 상세를 조회한다.
- 선택 결과는 저장 전 편집 폼에서 검토하고 수정할 수 있다.
- 선택 후 수정한 필드만 `UserEditedFields`에 기록된다.
- 저장하면 상태와 공급자 참조가 선택 결과에 맞게 교체된다.
- 취소 또는 조회·저장 실패 시 기존 레코드와 포스터가 변하지 않는다.
- 기존 자동 보강과 일반 편집 테스트가 계속 통과한다.
- 기본 테스트가 화면, 외부 네트워크와 사용자 데이터를 건드리지 않고 조용히 실행된다.
