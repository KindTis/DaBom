# DABOM 라이브러리 고정 툴바 UI delta 스펙

## 문서 성격

- 기존 DABOM Windows 데스크톱 앱의 메인 화면에서 라이브러리 툴바의 세로 위치 동작만 변경하는 UI delta 스펙이다.
- 대상 사용자는 마우스, 키보드 또는 보조 기술로 영상 보관함을 탐색하고 검색·정렬하는 DABOM 사용자다.
- 핵심 목적은 사용자가 긴 영상 목록을 탐색하는 동안 현재 스크롤 맥락을 잃지 않고 영상 수, 검색, 정렬 기능에 접근하게 하는 것이다.
- 주요 시나리오는 Featured 영역과 제목 영역을 지나 목록을 탐색하고, 고정된 툴바에서 검색하거나 정렬한 뒤 다시 화면 상단으로 돌아오는 흐름이다.

## MVP 범위와 상속

- 전체 제품의 사용자, 역할, 검색·정렬 규칙과 데이터 동작은 [DABOM 동영상 관리 프로그램 설계](2026-07-18-dabom-video-manager-design.md)에서 상속한다.
- 툴바의 기존 구성과 시각적 위계는 [DABOM 레퍼런스 UI 보완 설계](2026-07-19-dabom-reference-ui-polish-design.md)에서 상속한다.
- 영상 수, 검색 입력란, 정렬을 포함한 기존 라이브러리 툴바 전체를 하나의 단위로 고정한다.
- Featured 영역과 제목 영역은 기존처럼 메인 스크롤 영역과 함께 이동한다.
- 툴바의 내용, 너비, 가로 위치, 검색·정렬 상태, 바인딩, `Ctrl+K` 포커스, 키보드 탐색 순서와 접근성 이름은 상위 스펙의 기존 동작을 상속하며 변경하지 않는다.
- 기존 고정 하단 영역과 카드 상세 팝업의 표시·입력 동작을 상속하며 변경하지 않는다.
- 사용자 역할과 권한, 비즈니스 규칙 및 데이터의 생성·변경·보존·삭제 동작은 이 변경의 영향을 받지 않는다.
- 별도 툴바 복제, 축소형 툴바와 전환 애니메이션은 MVP 범위에서 제외한다.
- 이 문서의 모든 요구사항은 MVP 범위이며 별도의 후속 확장 범위는 없다.

## 용어와 상태

- **기준선**: 메인 스크롤 표시 영역 상단에서 18 DIP(장치 독립 픽셀) 아래인 수평선.
- **원래 상단**: 툴바를 고정하지 않았을 때 문서 흐름에서 툴바 상단이 표시될 세로 위치.
- **기본 상태**: 원래 상단이 기준선과 같거나 아래에 있어 툴바가 문서 흐름의 원래 위치에 표시되는 상태.
- **고정 상태**: 원래 상단이 기준선 위에 있어 툴바 상단이 기준선에 유지되는 상태.

## 사용자 흐름과 동작

1. 화면을 처음 열거나 툴바의 원래 상단이 기준선과 같거나 아래에 있으면 툴바는 기본 상태로 표시된다.
2. 아래로 스크롤해 원래 상단이 기준선을 지나면 툴바는 고정 상태가 되고, 이후 스크롤 중에도 상단이 기준선에 유지된다.
3. 고정 상태의 툴바는 영상 목록보다 앞에 표시되며, 두 영역이 겹치는 부분에서는 가려진 목록 항목 대신 툴바가 포인터 입력을 받는다.
4. 위로 스크롤해 원래 상단이 기준선과 같거나 아래로 돌아오면 툴바는 기본 상태로 복귀한다.
5. 창 크기, Featured 표시 상태, 검색 결과 또는 라이브러리 갱신으로 원래 상단이나 세로 스크롤 필요 여부가 바뀌면 레이아웃이 안정된 직후 추가 스크롤 없이 툴바 상태를 다시 판정한다. 세로 스크롤이 필요하지 않으면 기본 상태로 복귀하고, 필요하면 원래 상단이 기준선 위일 때 고정 상태를 유지하며 기준선과 같거나 아래일 때 기본 상태로 복귀한다.
6. 상태 전환 자체는 현재 키보드 포커스를 강제로 이동하지 않는다. 같은 툴바와 컨트롤을 유지하며 검색 텍스트, 정렬 선택과 접근성 정보가 초기화되거나 중복되지 않는다.

## 오류·복구 및 경계 조건

- 초기 표시 중 툴바 위치를 아직 판정할 수 없으면 기본 상태를 유지하고, 레이아웃이 안정되면 자동으로 다시 판정한다.
- 처음부터 콘텐츠가 짧거나 콘텐츠 변화로 세로 스크롤이 필요하지 않게 되면, 레이아웃이 안정된 직후 툴바는 추가 스크롤 없이 기본 상태가 된다.
- 툴바가 고정되거나 복귀할 때 콘텐츠의 스크롤 위치와 범위가 바뀌거나 화면이 눈에 띄게 튀지 않아야 한다.
- 허용되는 최소 창 크기와 100%·150% 화면 배율에서 툴바의 모든 내용이 표시·조작 가능해야 하며, 고정 하단 영역이나 세로 스크롤바와 충돌하지 않아야 한다.
- 이 변경은 사용자 입력 데이터나 저장 작업을 추가하지 않으므로 별도의 데이터 오류 안내 또는 복구 흐름을 만들지 않는다.

## 접근성 및 사용자 피드백

- 기본 상태와 고정 상태 모두 기존 포인터 입력, 키보드 탐색, Tab 순서, `Ctrl+K` 검색 포커스와 보조 기술 접근을 제공한다.
- 툴바는 사용자가 기존 Tab 순서로 이동하거나 `Ctrl+K`를 사용할 때 키보드 포커스를 받으며, 상태 전환만으로 현재 포커스를 가져오지 않는다.
- 상태 전환 때문에 접근성 트리에 같은 툴바나 컨트롤이 중복되어서는 안 된다.
- 고정 상태는 툴바 위치로 직접 확인할 수 있으며 별도 상태 문구나 알림은 추가하지 않는다.

## 수용 기준

1. 원래 상단이 기준선과 같거나 아래에 있으면 툴바가 원래 문서 위치에 표시된다.
2. 원래 상단이 기준선 위로 이동하면 툴바 상단이 기준선에 유지되고, 나머지 콘텐츠는 계속 스크롤된다.
3. 위로 스크롤해 원래 상단이 기준선과 같거나 아래로 돌아오면 툴바가 눈에 띄는 점프 없이 원래 위치로 복귀한다.
4. 창 크기, Featured 표시 상태, 검색 결과 또는 라이브러리 갱신으로 원래 상단이나 세로 스크롤 필요 여부가 바뀌면 추가 스크롤 없이 레이아웃이 안정된 직후 현재 조건에 맞는 기본 상태 또는 고정 상태로 전환된다.
5. 처음부터 세로 스크롤이 필요하지 않거나 검색 결과 감소 등으로 필요하지 않게 되면 툴바는 기본 상태를 유지하거나 추가 스크롤 없이 복귀한다.
6. 고정 상태에서도 영상 수, 검색, `Ctrl+K`, 정렬, 포인터 입력과 접근성 이름이 기존과 동일하게 동작한다. 상태 전환은 현재 키보드 포커스를 강제로 이동하거나 검색·정렬 상태를 초기화하지 않는다.
7. Featured 영역과 제목 영역은 계속 스크롤되고, 고정 하단 영역과 카드 상세 팝업의 표시·입력 동작은 바뀌지 않는다.
8. 허용되는 최소 창 크기의 100%·150% 화면 배율에서 툴바 내용이 잘리거나 고정 하단 영역 및 세로 스크롤바와 충돌하지 않는다.

## 제약 및 남은 리스크

- 스크롤과 콘텐츠·레이아웃 변화가 연속으로 발생할 때 툴바가 기준선을 벗어나거나 상태가 반복 전환되는 현상은 출시 blocker다.
- 고정 또는 복귀 과정에서 스크롤 위치가 바뀌거나 검색·정렬 입력이 끊기는 현상은 출시 blocker다.
- 구현 방식과 테스트 구성은 후속 구현 계획에서 정하며 이 스펙의 외부 동작을 변경할 수 없다.
- 미결정 항목과 후속 검토 항목은 없다.
