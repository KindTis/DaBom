# DABOM 라이브러리 툴바 플로팅 설계

## 목표

메인 화면의 Featured 영역과 제목 영역은 기존처럼 스크롤되게 두고, 전체 `LibraryToolbar`가 스크롤 영역 상단에 도달하면 영상 목록 위에 떠서 유지한다. 사용자가 최상단으로 돌아오면 툴바는 원래 문서 위치로 복귀한다.

## 범위

- 영상 수, 검색 입력란, 정렬을 포함한 기존 `LibraryToolbar` 전체를 유지한다.
- 기존 검색 바인딩, `Ctrl+K` 포커스, 정렬, 접근성 이름을 변경하지 않는다.
- 기존 `LibraryFooter` 고정 구조와 카드 팝업 관련 작업 트리 변경을 보존한다.
- 별도 툴바 복제, 축소형 툴바, 전환 애니메이션은 추가하지 않는다.

## 동작

1. 툴바가 원래 위치에 있을 때는 이동 변환을 적용하지 않는다.
2. 툴바의 원래 상단이 스크롤 영역 상단에서 18px 위치를 지나면, 필요한 거리만큼 아래로 이동해 18px 위치를 유지한다.
3. 플로팅 툴바는 영상 목록보다 높은 표시 순서를 사용해 목록 위에 그려지고 입력도 그대로 받는다.
4. 위로 스크롤해 툴바의 원래 위치가 다시 18px 아래로 내려오면 이동값을 0으로 되돌린다.
5. 창 크기나 Featured 표시 상태가 바뀌어 원래 위치가 달라져도 현재 화면 좌표와 기존 이동값으로 새 이동값을 계산한다.

## 구조

`MainWindow.xaml`의 메인 `ScrollViewer`에 이름과 `ScrollChanged` 처리기를 연결한다. 기존 `LibraryToolbar`에는 `TranslateTransform`과 높은 `Panel.ZIndex`만 추가한다. 툴바의 부모나 바인딩은 바꾸지 않는다.

`MainWindow.xaml.cs`의 스크롤 처리기는 현재 툴바 화면 좌표에서 기존 이동값을 제외해 원래 좌표를 구한다. 새 이동값은 다음 규칙 하나로 계산한다.

```text
새 이동값 = max(0, 18 - 원래 상단 좌표)
```

이 방식은 같은 툴바 인스턴스를 이동하므로 검색 텍스트, 포커스, 정렬 선택 상태를 동기화하는 별도 코드가 필요 없다.

## 오류 및 경계 조건

- 레이아웃이 아직 준비되지 않은 초기 이벤트에서는 이동을 적용하지 않는다.
- 스크롤이 필요 없는 짧은 화면에서는 이동값이 계속 0이다.
- 플로팅은 `RenderTransform`만 사용하므로 문서 레이아웃 높이와 스크롤 범위를 변경하지 않는다.
- 별도 데이터 처리나 저장 작업이 없으므로 사용자 데이터 오류 경로는 추가되지 않는다.

## 검증

- 툴바가 상단 기준점에 도달하기 전에는 이동값이 0이다.
- 기준점을 지난 만큼만 양수 이동값이 계산된다.
- 위로 돌아오면 이동값이 다시 0이 된다.
- XAML에 단일 `LibraryToolbar`, 스크롤 이벤트, 이동 변환, 표시 순서가 존재한다.
- 검색, `Ctrl+K`, 정렬 바인딩과 기존 `LibraryFooter` 구조가 유지된다.
- 전체 Release 테스트와 Release 빌드가 통과한다.
