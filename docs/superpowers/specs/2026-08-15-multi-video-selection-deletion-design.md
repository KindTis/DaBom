# 다중 영상 선택 및 삭제 설계

## 문서 성격

- 기존 DABOM 메인 영상 목록의 단일 선택과 단건 삭제를 확장하는 delta 스펙이다.
- 기존 영상 삭제의 파일 상태 확인, 파일 식별자 재검증, 휴지통 이동 및 라이브러리 저장 규칙은 유지한다.
- 기존 TV 시즌 카드의 일괄 삭제 금지 정책과 삭제 확인 창의 테마·취소 우선 정책을 유지한다.

## 목표

1. 사용자가 `Shift`로 연속 범위를, `Ctrl`로 떨어진 항목을 다중 선택할 수 있게 한다.
2. 선택한 실제 영상들을 한 번의 확인 후 `DEL`로 삭제할 수 있게 한다.
3. 목록의 기준이 바뀌거나 사용자가 일반 클릭으로 다른 항목을 선택하면 이전 다중 선택을 해제한다.
4. 다중 선택 중에는 메타데이터 편집을 시작할 수 없게 한다.
5. 삭제 확인 창에 모든 삭제 대상과 처리 방식을 표시하되, 항목이 많으면 목록만 내부 스크롤한다.
6. 일부 삭제가 실패해도 안전하게 처리할 수 있는 나머지 항목은 계속 처리한다.

## 선택한 접근

WPF `ListBox`의 기본 확장 선택을 사용하고, 파일 변경은 기존 `MainViewModel` 삭제 경로에서 처리한다.

- `SelectionMode="Extended"`가 제공하는 `Shift`, `Ctrl` 및 일반 클릭 동작을 그대로 사용한다.
- `ListBox.SelectedItems`는 WPF가 직접 관리한다. 별도의 선택 바인딩 동작이나 선택 서비스는 만들지 않는다.
- 창은 선택 변경 시 선택 개수와 삭제 대상 스냅샷만 `MainViewModel`에 전달한다.
- 검색·필터·정렬 변경 감지는 `MainWindow`가 이미 구독하는 `MainViewModel.PropertyChanged`를 재사용한다.
- 다중 삭제는 기존 단건 삭제의 안전 검사를 공통 내부 경로로 재사용한다.
- 새 패키지, 범용 대화상자 프레임워크와 선택 관리 추상화는 추가하지 않는다.

## 선택 동작

### 기본 선택

- 첫 영상 클릭은 기존처럼 한 항목을 선택한다.
- 선택된 영상을 기준점으로 두고 다른 영상을 `Shift` 클릭하면 현재 화면 순서에서 두 항목 사이의 범위를 모두 선택한다.
- `Ctrl` 클릭은 선택 집합에서 해당 항목을 추가하거나 제거한다.
- 보조키 없이 다른 항목을 클릭하면 기존 다중 선택을 해제하고 클릭한 항목만 선택한다.
- 선택 강조 표시는 현재 `ListBoxItem.IsSelected` 기반 테두리 스타일을 모든 선택 항목에 그대로 적용한다.

### TV 시즌 카드

- 시즌 카드는 삭제 대상에 포함하지 않는다.
- 영상과 시즌 카드가 함께 선택되면 시즌 카드가 제외됐음을 안내하고 실제 영상만 삭제 확인 대상으로 사용한다.
- 시즌 카드만 선택된 상태에서 `DEL`을 누르면 기존 안내를 표시하고 확인 창을 열지 않는다.
- 시즌 카드 자체의 일괄 삭제와 시즌 안의 모든 에피소드 자동 선택은 추가하지 않는다.

## 선택 초기화

다음 값이 실제로 변경되면 현재 선택을 모두 해제한다.

- 메인 검색어 `SearchText`
- 영상 필터 `SelectedFilter`
- 정렬 기준 `SelectedSort`
- 정렬 방향 `IsSortDescending`

`MainWindow`의 기존 `PropertyChanged` 처리에서 해당 속성을 감지해 `VideoList.UnselectAll()`을 호출한다. 선택 해제는 `SelectedItem`, 선택 개수와 명령 상태에 즉시 반영한다. 같은 값을 다시 설정한 경우에는 변경 알림이 없으므로 별도 초기화를 수행하지 않는다.

## 메타데이터 편집 제한

- 선택 개수가 정확히 1개이고 그 항목이 실제 영상일 때만 메타데이터 편집을 허용한다.
- 2개 이상 선택하면 메타데이터 편집 명령의 `CanExecute`를 `false`로 만들고 F1 진입도 같은 명령 상태를 따른다.
- UI 명령 검사만 믿지 않고 `CreateMetadataEditor`에서도 같은 조건을 확인한다.
- 시즌 카드 한 개, 선택 없음 또는 라이브러리 변경 불가 상태에 대한 기존 차단 규칙은 유지한다.
- 재생은 이번 변경 범위에 포함하지 않으며, Enter와 더블 클릭은 현재 단일 대상에 대한 기존 동작을 유지한다.

## 다중 삭제 흐름

1. 영상 목록에 포커스가 있는 상태에서 사용자가 `DEL`을 누른다.
2. 창은 현재 선택 항목을 즉시 스냅샷으로 만든다. 이후 화면 선택이 바뀌어도 이 삭제 요청의 대상은 바뀌지 않는다.
3. 시즌 카드는 제외하고, 포함됐다면 기존 방식의 안내를 표시한다.
4. 각 영상에 대해 현재 파일 상태와 실제 파일 식별자를 확인한다.
5. 안전하게 준비할 수 없는 영상은 삭제 대상에서 제외하고 실패 항목으로 기록한다. 준비 가능한 영상이 하나도 없으면 확인 창을 열지 않고 결과를 알린다.
6. 확인 창에 준비된 모든 영상의 파일명과 처리 방식을 표시한다.
7. 사용자가 명시적으로 삭제 버튼을 실행하면 준비된 요청을 순서대로 처리한다.
8. 각 영상은 실제 변경 직전에 파일 상태와 식별자를 다시 확인한다.
9. 한 항목이 실패하면 해당 항목의 파일과 마지막 저장 성공 상태를 보존하고 다음 요청을 계속 처리한다.
10. 모든 처리가 끝나면 성공 개수와 실패 개수를 한 번에 알린다.

선택 항목이 하나뿐이어도 같은 흐름을 사용해 기존 단건 삭제와 다중 삭제가 서로 다른 안전 규칙을 갖지 않게 한다.

## 삭제 확인 창

- 창 제목과 본문 제목은 기존 `영상 삭제`, `영상을 삭제할까요?`를 유지한다.
- 삭제 대상마다 파일명과 다음 처리 방식 중 하나를 한 행에 표시한다.
  - 실제 파일 있음: `휴지통으로 이동하고 목록에서 제거`
  - 실제 파일 없음: `목록에서만 제거`
- 전체 파일 경로는 표시하지 않는다.
- 한 항목일 때도 동일한 목록 표현을 사용한다.
- 목록은 내용에 맞춰 늘어나되 최대 높이를 둔다. 최대 높이를 넘으면 목록 내부에 세로 스크롤바를 표시하며 창 전체가 계속 커지지 않게 한다.
- 확인 버튼 문구는 상태가 섞일 수 있으므로 `선택 항목 삭제`로 통일한다.
- 취소 버튼은 기존처럼 초기 포커스와 기본 동작을 가지며, `Escape`와 창 닫기는 삭제하지 않는다.
- 목록의 각 행과 버튼은 화면 읽기 프로그램에서 파일명과 처리 목적을 구분할 수 있는 자동화 이름을 제공한다.

## 데이터 일관성과 오류 처리

- 파일이 있는 항목은 기존처럼 휴지통 이동에 성공한 뒤 라이브러리 저장을 시도한다.
- 파일이 없는 항목은 실제 파일 작업 없이 라이브러리 저장만 시도한다.
- 휴지통 이동 실패 시 해당 항목을 목록에서 제거하지 않는다.
- 휴지통 이동 후 라이브러리 저장이 실패하면 기존처럼 화면 항목을 파일 없음 상태로 유지한다.
- 확인 전후에 파일 상태나 식별자가 달라지면 해당 항목을 삭제하지 않는다.
- 성공한 항목만 현재 화면과 저장 데이터에서 제거한다.
- 삭제 작업 전체가 진행되는 동안 기존 변경 명령 비활성화 상태를 유지한다.
- 항목별 실패 토스트를 대량으로 쌓지 않고, 작업 종료 후 성공·실패 개수를 요약해 알린다.

파일 휴지통 이동과 JSON 저장은 원자적 작업이 아니므로 기존 부분 실패 복구 정책보다 강한 트랜잭션을 새로 만들지 않는다.

## 구현 경계

- `MainWindow.xaml`은 기본 확장 선택과 선택 변경 이벤트를 연결한다.
- `MainWindow.xaml.cs`는 선택 개수 동기화, 검색·필터·정렬 변경 시 선택 해제, `DEL` 대상 스냅샷과 확인 창 표시를 담당한다.
- `MainViewModel`은 메타데이터 명령 상태, 다중 삭제 준비, 기존 안전 검사 재사용, 순차 처리와 결과 요약을 담당한다.
- `VideoDeletionConfirmationWindow`는 삭제 대상 목록을 표시하고 확인 여부만 반환한다. 파일 확인이나 삭제는 수행하지 않는다.
- 기존 `LibraryStore`, `WindowsFileOperations`, JSON 형식과 영상·시즌 ViewModel 형식은 변경하지 않는다.

## 검증

사용자 화면을 띄우지 않는 기존 MSTest와 XAML 정적 검사를 우선한다.

1. 영상 목록이 WPF 확장 선택을 사용하고 선택 변경 처리가 연결돼 있는지 확인한다.
2. 검색어, 필터, 정렬 기준과 정렬 방향을 변경하면 선택 개수가 0이 되는지 확인한다.
3. 선택 개수가 2개 이상이면 메타데이터 명령과 편집기 생성이 차단되는지 확인한다.
4. 실제 영상 한 개만 선택하면 기존 메타데이터 편집이 계속 가능한지 확인한다.
5. 시즌 카드가 삭제 요청에서 제외되고, 실제 영상이 없으면 기존 시즌 삭제 안내만 표시되는지 확인한다.
6. 파일 있음과 파일 없음이 섞인 삭제 대상이 각각 올바른 처리 방식으로 준비되는지 확인한다.
7. 확인 창이 모든 대상의 파일명과 처리 방식을 표시하고 목록에 최대 높이와 내부 세로 스크롤을 적용하는지 확인한다.
8. 다중 삭제 중 한 항목의 준비, 상태 재검증, 휴지통 이동 또는 저장이 실패해도 다음 항목을 계속 처리하는지 확인한다.
9. 성공한 항목만 화면과 저장 데이터에서 제거되고 성공·실패 개수가 정확히 요약되는지 확인한다.
10. 기존 단건 삭제의 상태 변경, 파일 식별자, 휴지통 이동 실패와 저장 실패 테스트가 계속 통과하는지 확인한다.
11. 변경과 직접 관련된 테스트와 Debug 빌드가 성공하는지 확인한다.
12. 코드 변경 후 `graphify update .`가 성공하는지 확인한다.

## 수용 기준

1. `Shift` 연속 선택, `Ctrl` 개별 선택과 일반 클릭의 단일 선택 전환이 동작한다.
2. 검색·필터·정렬 기준·정렬 방향 변경 시 선택이 완전히 초기화된다.
3. 다중 선택 중에는 F1을 포함한 메타데이터 편집 진입이 불가능하다.
4. `DEL` 확인 창에 삭제할 모든 실제 영상과 각 처리 방식이 표시된다.
5. 삭제 대상이 많아도 확인 창은 목록 내부 스크롤을 사용해 비대하게 커지지 않는다.
6. 시즌 카드는 삭제되지 않으며 사용자에게 제외 사실을 알린다.
7. 일부 항목이 실패해도 나머지를 계속 처리하고 최종 성공·실패 개수를 알린다.
8. 기존 단건 삭제의 파일 안전성과 저장 정합성 정책이 유지된다.

## 제외 범위

- 시즌 전체 또는 시즌 카드 일괄 삭제
- 마우스 드래그 영역 선택과 선택 반전
- 선택 항목에 대한 일괄 메타데이터 편집
- 삭제 순서 변경, 재시도 버튼, 실행 취소와 휴지통 복원
- 선택 상태의 영속 저장 또는 필터·정렬 변경 후 복원
- 새 선택 관리 프레임워크나 외부 패키지
